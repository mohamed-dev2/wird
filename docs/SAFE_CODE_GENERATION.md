# Safe code generation

Wherever generated or derived artifacts ship in this repo, the boundary
between **editable source** and **generated output** must be unambiguous,
and regeneration must never silently clobber human-authored work.

## What is generated today

| artifact                                                     | kind                                   | editable source?              | tooling                          |
| ------------------------------------------------------------ | -------------------------------------- | ----------------------------- | -------------------------------- |
| `public/data/*.min.json` (quran/tafsir/hadith/bip39)         | derived from reviewed upstream sources | no — treat as output          | out-of-repo pipeline (see below) |
| `next-env.d.ts`                                              | build-generated by Next                | no — regenerated on build/dev | `next dev`/`next build`          |
| `.next/`, `node_modules/`, `test-results/`, `sbom.wird.json` | build/test outputs                     | no                            | npm/next/playwright              |

## Rules

1. **Marker files claim their provenance.** `public/data/README.md` and
   the section comments in `app/lib/data/*.ts` state that content ships
   data, not hand-edited code. Every generated artifact should be
   discoverable as such in one hop.
2. **Editable source never hides next to generated output.** Curated,
   human-maintained catalogs live in `app/lib/data/*.ts` (source).
   Derived bundles live in `public/data/` (output). Never mix the two in
   one directory.
3. **Regeneration must not overwrite human edits.** Any future pipeline
   that writes `public/data/*.min.json` must fail loudly (or refuse) if
   the source catalogs and the generated files have diverged (e.g. a
   checksum or content hash check before writing).
4. **One pipeline, one source of truth.** When the producing tooling is
   added to this repo it belongs in `scripts/` with a `README.md` entry,
   a `SOURCE → GENERATOR → OUTPUT` note in this file, and a unit test that
   regenerating from the same source yields byte-identical output.
5. **AI-assistance is not code generation.** Mechanisms like an LLM
   autocompleting code are subject to the normal review/gate process
   (AGENTS.md), not to this section.

## Current state disclaimer

The `public/data/*.min.json` bundles are the result of an upstream,
out-of-repo pipeline. Until that pipeline is checked in, contributors must
not hand-edit them; changes go through the source + the
religious-content review process and are then regenerated and checked in
by a maintainer.
