# ADR-003 — Analytics architecture

Status: accepted

## Context

We wanted calendar/insight features (trends, heatmaps, milestones) but
wanted to avoid both (a) sending data anywhere and (b) a slow, O(n²)
computation on multi-year histories.

## Decision

Analytics is a **pure, deterministic layer**: `app/lib/history.ts` (day
records + sliding windows) feeds `app/lib/analytics.ts` (metrics, trends,
insights) which feeds `app/lib/coach.ts` (a short human brief). All
functions are pure; the UI (`/insights`, `/deen` review tab, camera-roll
views) renders their output. Nothing is computed server-side.

## Alternatives

- Precompute aggregates on write: rejected — write path was already
  transaction-heavy; recompute-on-demand is fast enough at this scale.
- Streaming/online learner: rejected — violates explainability and
  testability; every rule must have a below-threshold test.

## Reason

Deterministic pure functions are unit-testable (17+ suites), cheap to
profile, and give the team "no data left the device, here's the exact
formula" as an auditable claim (docs/ANALYTICS.md).

## Consequences

- Insight rules must be added with a negative (below-threshold) test —
  this is CI-enforced by review convention and documented in CONTRIBUTING.
- Complexity lives in `analytics.ts`; hot paths are annotated with their
  cost so O(n²) regressions are caught in review and by
  docs/PERFORMANCE.md guidance.
- Calendar/coach consumers must not add their own ad-hoc derivations —
  keep derivations in the analytics layer to stay testable.
