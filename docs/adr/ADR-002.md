# ADR-002 — No cloud AI

Status: accepted

## Context

Early versions of Wird experimented with transcribing voice memos via a
cloud transcription service. That meant daily spoken reflections — the
most sensitive content in the product — transited a third party.

## Decision

No cloud AI, no server-side processing, no transcription. Adaptation and
insight logic run entirely client-side in pure TypeScript
(`app/lib/companion.ts`, `app/lib/analytics.ts`). Voice logging was
removed entirely (audio.ts keeps only playback of recitation, CSP
allowlisted).

## Alternatives

- Keep cloud transcription "optional": rejected — the guarantee must be
  simple enough to state without conditions.
- On-device speech-to-text via Web Speech API: rejected for now because
  browser speech engines vary wildly and would break the deterministic,
  tested behavior of the rest of the app. Revisit if a single reliable
  offline engine appears.

## Reason

A religious practice tracker must be trustworthy in a way that doesn't
depend on a price sheet. Data that "could leave" is data that will be
shared.

## Consequences

- Companion/analytics reasoning is testable pure functions (great for the
  open-source project). No model weights, no inference latency, no per-user
  training data — nothing to leak.
- Feature richness is bounded by what local heuristics can honestly do;
  the docs (COMPANION.md, ANALYTICS.md) deliberately name the limits
  rather than pretending to more intelligence.
