# ADR-007 — Deen progression model (STEP 10)

Status: accepted

## Context

Wird needed a motivational self-improvement layer (levels, XP, quests,
streaks) over Islamic practice without turning religion into a
scoreboard, diagnosing users, or inventing rulings, rewards, or
classifications. All state must live in the existing local-storage
system (no database).

## Decision

We will model progression as **tracking depth, never rank**: Deen Levels
1–5 unlock categories the user tracks (fard → mustahabb → makruh
awareness → character → refinement), chosen voluntarily, downgradable
without data loss. **Wird XP** measures in-app activity only (never
hasanat, faith, or divine reward). There are no sin counters, no
negative XP, no religious leaderboards, no faith percentages, and no
"sin-free" streaks — each absence is asserted by test. Catalog content
separates `verified` (sourced) from `personal-goal` / `habit` /
`advice`; unverified specifics are labeled honestly, never upgraded.

## Consequences

Good: engaging without theologically loaded claims; firewall keeps deen
data out of analytics/shares/notifications; one per-profile key
(`wird-deen-v1`) with idempotent XP ledger (no double-award).
Hard: catalog classifications need reviewer sign-off before they can be
called more than summaries (flagged in CONTENT_RIGHTS.md); streaks
inherit the device-clock limitation (LIMITATIONS.md).
