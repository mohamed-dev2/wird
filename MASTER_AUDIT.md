# Master Audit — Wird (STEP 9)

Local-first scope note first: Wird has **no backend, no accounts, no
server sessions, no roles, no push infrastructure**. Audit items written
for a client/server product are mapped to their on-device equivalent;
where no equivalent exists the item is marked `N/A (local)` with the
reason instead of theater. Statuses: `PASS` (evidenced), `FIXED` (found

- repaired in this audit), `PARTIAL` (covered, known gap roadmapped),
  `N/A (local)`, `BLOCKED` (cannot run from this environment),
  `NEEDS_REVIEW` (needs a human/device the CI does not have).

Machine inventory: `audit/` (`audit-manifest.json`, `routes.json`,
`features.json`, `permissions.json`, `integrations.json`,
`test-matrix.json`), regenerated by `npm run audit:manifest`
(`scripts/generate-audit.mjs`, derives from the repo — never hand-edit
the JSONs). This run's numbers: `AUDIT_REPORT.md`. Frozen snapshot:
`AUDIT_BASELINE.md`.

## 10–16. Religious content accuracy — PASS (process, not proof)

- Engine: sourced packs with `source`/`grade` metadata, coverage ledger
  (`docs/features/*`, `CONTENT_RIGHTS.md`), no AI fatwa surface (coach

  theologically certify content; it certifies the _process_: every
  user-facing religious string is traceable to a pack + grade, packs are
